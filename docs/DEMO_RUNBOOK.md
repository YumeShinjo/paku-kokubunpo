# 発表会(デモ)運用メモ

発表本番で確実に動くことを最優先にするための、事前確認・当日手順・トラブル時の対処。

## 1. 公開URLと、当日のクラスコード

- 公開URL: `https://paku-kokubunpo.web.app/`
- **クラスコードは、コードの変更なしに、当日いつでも自由に決められる**(参加画面で入力するだけ。事前登録・デプロイは不要)。
- **共有URLで入力の手間を省ける**: URLの末尾に `?class=合言葉` を付けると、ランキング参加画面のクラスコード欄に最初から入る。
  - 例: `https://paku-kokubunpo.web.app/?class=hakuhyou2026`
  - このURLをスライドやQRコードで配れば、みんなが同じクラスに入れる(打ち間違いを防げる)。
  - 日本語のコードも使えるが、URLに入れると読みにくいので、英数字が無難。
- 合言葉は推測されにくいものにする(短い一般的な単語だと、他のクラスの人に順位を見られる)。
  例: `demo-` + 日付や乱数(`demo-0929-k7q`)。
- **リハーサル用と本番用でコードを分ける**(本番の順位表を空から始めるため)。例: リハーサル `rehearsal-xxxx`、本番 `demo-xxxx`。

### 順位表のリセット・後片付け
- 発表者の端末: ランキング画面の「クラスを ぬける」で自分のデータが消える。別のコードで入り直せば別のクラスになる。
- リハーサルで使ったクラスをまるごと消す(自分のPCで、ログイン済みの Firebase CLI から):

  ```bash
  npx firebase-tools firestore:delete /classes/リハーサルのコード --recursive
  ```

  (Firebaseコンソールの Firestore Database でも、`classes` → 該当のコード → `members` を削除できる)

## 2. 事前チェックリスト(前日までに)

1. **最新版を公開しておく**(`npm run build` → `npx firebase-tools deploy --only hosting`)。**前日以降はデプロイしない**(直前の変更が一番の事故のもと)。
2. 発表に使う端末(PC・スマホ)で、公開URLを開いて一通り遊ぶ(出題 → 小ボス → ストーリー → エンディング → ランキング)。
3. **PWAとして入れておく**(スマホ: ホーム画面に追加。PC: Chromeのインストール)。一度開いて遊べば、オフラインでも起動できる。
4. **機内モード(またはWi-Fiオフ)で、起動 → 1ステージ遊べる**ことを確認する。
5. 会場のWi-Fiで、ランキングに参加できることを確認する(可能なら会場で事前に)。会場の回線が不安なら、**スマホのテザリングを予備に用意**する。
6. 音: 端末の音量とマナーモード(iPhoneは消音スイッチ)を確認する。最初の1タップで解禁される。
7. デモ用のセーブデータ: 発表用の端末は、事前に**進捗を初期化した状態か、見せたい進み具合の状態**にしておく(ブラウザの保存データは端末ごと。デモ前に「サイトデータを消す」か、シークレットウィンドウで開けば最初から始められる)。

## 3. 当日の流れ・注意

- 発表者は、**まずオフラインで動く前提のコア機能(出題・ストーリー・成長・図鑑)でデモ**し、ランキングは通信が確認できてから見せる。
- 参加してもらう人が多い場合は、共有URLを配る → 各自「ランキング」→「さんかする」→ ニックネームを入れる。
- ニックネームは、NGワードのチェックが入る(表記ゆれはすり抜けることがある)。ふざけた名前が出たら、表示を見せる前に確認する。

## 4. 通信・負荷の見積もり(無料枠で足りるか)

Firebase の無料プラン(Spark)の上限の目安: Firestore は 1日 読み取り5万回・書き込み2万回。

| 想定 | 回数 |
| --- | --- |
| 40人が、順位を10回ずつ開く | 読み取り 約1.2万回(1回の表示で最大約31件) |
| 40人が、ステージを20回ずつクリアして得点を送る | 書き込み 約800回 |

→ 数十人規模なら余裕。**アプリはリアルタイム購読をしない**(開いたときと「こうしん」でだけ取得)ので、読み取りが急増しにくい。

匿名認証(初回のログイン)には、同じ回線から短時間に大量に作れない制限がある(1つのIPアドレスから1時間あたり約100件が目安。公式の値は変更されうる)。
教室単位(数十人)なら問題ないが、**数百人が同じ会場Wi-Fiから一斉に参加する場合は、この上限に近づく**。

## 5. 確認済みの動作(2026-09-21)

| 項目 | 結果 |
| --- | --- |
| 25人が同時に匿名ログインして、同じニックネームで同時に参加 | 全員成功。IDは25個とも別。同じニックネームでも衝突しない(表示は同名が並ぶだけ) |
| 25人が得点を連続で書き込み(各5回) | 全員成功。最終得点は全員が期待どおり。順位は得点の降順で、圏外の人の順位も正しく出る |
| 同じ人が2つの画面から同時に500点と450点を送る | 高いほう(500)が残り、低いほうはルールで拒否される(得点は減らない) |
| サーバーを止めた状態(オフライン)で、全8エリアの通常ステージを通しで遊ぶ | すべてクリアできた。ネットワーク通信は0件。進捗と得点は保存された |
| オフラインで `?class=` 付きのURLを開く | 開けて、クラスコード欄に初期値が入った |
| 最初の状態から、全8エリアを全問正解で通しプレイ(通常ステージ・小ボス7・ラスボス・エンディング・クレジット) | 詰まりなく最後まで到達。全問題が自動照合で解答でき、ストーリー全フェーズが再生され、成長は最終段階、称号が付与された。再読み込みしても進捗・称号は保持される |
| 公開URLで新版に更新されるか | 更新後の1回目の読み込みは旧版のことがあり、2回目から新版になる(アプリを閉じて開き直す) |
| 通信が返ってこないとき | 10秒で打ち切って「つうしんできない」と表示(画面や得点の送信が固まらない)。通信が戻れば再送される |

## 6. 既知の注意点

- **BGMはオフラインでは鳴らない**(効果音は鳴る)。BGM素材が入ったら、会場で音を確認する。
- ランキングに参加するには、初回だけ通信が必要(オフラインでは参加も順位の取得もできない。遊ぶことはできる)。
- ブラウザの保存データを消すと、ランキング上は別人になる(以前のデータは残る)。デモ前に消すときは、先に「クラスを ぬける」を押す。
- 得点はアプリが計算して送る仕組みなので、悪意のある端末が自分の得点を盛ることは防げない(他人のデータの改ざんや桁外れの値は防いでいる)。
