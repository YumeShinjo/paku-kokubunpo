# 4. 出題の仕組み

出題の3つの型(と、文中タップ)、正誤判定、解説、問題の選び方、苦手問題(星)、正答率と「にがて」、復習をまとめる。ボス戦だけのルール(HP・ライフなど)は5章。

## 4.1 出題データ

出題データは、型付きのデータとして `src/data/questions/<エリア>/` に置く(`.ts`)。画面のコードとは分かれている。

|---|---|---|

## 4.2 出題の型(エンジン)

3つのエンジンで、全単元をまかなう(`src/engines/EngineRouter.tsx`)。判定は共通(`src/engines/core/judge.ts`)。**1問につき判定は1回だけ**で、解答が確定したあとは、選択肢・カード・「こたえる」を押せない(`disabled`)。再描画を待たずに続けて押されても、最初の1回だけが解答になる(各エンジンと `QuizPlayer` の両方で守っている)。

### (1) 選択式(`choice`・通常)

- 問題文(と、あれば場面の説明)の下に、選択肢のボタンが縦に並ぶ。タップした時点で解答が確定する。
- 解答後、選んだものと正解が色分けされ、色だけに頼らないよう、正解に「◎」、選んでしまった不正解に「×」が付く。
- 正解の位置は、データの作り方で偏らないようにしている(`createChoiceArranger`)。

### (2) 選択式(文中タップ)

- `display: "tapInSentence"`。文の文節がボタンとして並び、答えだと思う文節をタップする。文節のうち `given: true` のものは「問いの基準」で、強調して出し、タップできない。
- 判定・結果の見せ方は、通常の選択式と同じ。独立したエンジンではなく、選択式の表示モード。絆の間だけで使う。

### (3) 組み立て(`assembly`・穴埋め)

- 空欄(`___`)を含む文と、カード3枚。カードをタップして選ぶと、空欄にその文字が入る。選び直せる。
- 「こたえる」は、画面の下に固定した専用の枠にある。カードを選ぶまでは押せない。押すと確定する。

### (4) 仕分け(`sorting`)

- 操作は2通り(結果は同じ): **ドラッグ&ドロップ**(語のカードをカゴへ運ぶ。マウス・ペンは Pointer Events、指は Touch Events)と、**タップ選択**(語をタップして選び、カゴのボタンをタップして入れる)。
- 入れた語は、カゴの中に並び、別のカゴへ入れ直せる。ドラッグ中、画面の上下の端に近づくと、自動でスクロールする。
- 同じ表記の語が複数ある問題(例: 「ある」が2枚)には、①②の番号が付く(番号の付け方は、画面を開くたびにシャッフルする)。カゴに入れた語は、対象の語だけの小さな表示になるので、「もんだいぶんを みる」の欄で文を見られる(同じ表記の語がある画面では、はじめから開いている)。
- 全部を入れると「こたえる」が押せる。**1回だけやり直せる**: 1回目に1枚でも外すと、外したカードだけがカゴから戻り、合っているカードは固定される(答えや品詞名は出さない。「あと○枚 ちがうよ」と出る)。2回目の「こたえる」で確定する。
- 解答として通知されるのは、**1回目の入れ方**。判定・星・正答率は、1回目で決まる。1回目に外して、2回目で全部合ったときは、集計は不正解のまま、表示だけ「2かいめで せいかい!」(と、復習をすすめる一言)になる。
- 解答後は、語ごとの正誤(◎/×)と、語ごとの解説が出る。品詞分類で正解した語には、品詞の色札(色+品詞名)が付く(7章)。

### 判定の規則(`judgeAnswer`)

| 型 | 正解の条件 |
|---|---|
| 選択式 | 選んだ選択肢のidが、`correctChoiceId` と一致する |
| 組み立て | 選んだカードの並びが、`correctOrder` と、長さも順番も一致する |
| 仕分け | **すべての語**が、正しいカゴに入っている(1語でも違えば不正解。入れていない語は誤り) |

型が合わない解答(例: 選択式の問題に、仕分けの解答)は、例外を投げる。

## 4.3 解答のあとに出るもの

| 項目 | 内容 | 根拠 |
|---|---|---|
| 判定のポップアップ | 正解/不正解を、コトの表情(正解=喜び、不正解=しょんぼり)と一言で示す。**自動では消えない**。出た直後の400ミリ秒は、画面のタップでは閉じない(誤タップ防止) | `QuizPlayer.tsx` |
| 解説 | 選択式・穴埋めは、判定と解説を1つのポップアップにまとめ、「つぎへ」(または背景のタップ)で次へ。仕分けは、判定だけのポップアップ(タップで閉じる)のあと、画面下の解説の枠と「つぎへ」で次へ(解説を読み飛ばさないため) | 同上 |
| 正解の一言 | 7通りから、直前と同じものを避けて選ぶ(「もぐもぐ…おいしい!」「せいかい!」「いいね!その調子!」「ばっちり!」「ぴったり!コトが元気になった!」「すごい!」「おみごと!」) | `src/data/feedbackMessages.ts` |
| 不正解の一言 | 5通り(「おしい!もう少し!」など)。ボス戦では、命中=4通り(「ヒット!」など)、はずれ=3通り(「はずれた!でも大丈夫」など) | 同上 |
| 正解の演出 | 3種(`pop`・`sparkle`・`shine`)から、直前と同じものを避けて選ぶ。OSの「動きを減らす」設定では、アニメーションを止める | `src/features/quiz/feedback.ts` |
| コンボ | 2連続以上で、ステージの上に「N れんぞく!」を出す。5連続以上(`COMBO_EXCITED_THRESHOLD = 5`)で、正解のときのコトの表情が、テンション高めになる。結果画面には、最大の連続数も出る | 同上、`QuizPlayer.tsx` |
| 「にがて克服!」 | 「にがて」の単元(4.7)の問題に正解したときに、演出として出る。得点などのボーナスはない | `QuizPlayer.tsx`(`weakBonus`) |
| 「にがてを こくふくした!」 | 星のついた問題に正解して、星が外れたとき。コトが「もぐもぐ」の表情になり、克服の効果音が鳴る | `QuizPlayer.tsx`、`review.ts` |
| 「パクっと」の説明 | 最初の正解のポップアップに、1度だけ「コトは、正しいことばを パクっと 食べて 元気になるよ」と出る(閉じたら既読) | `engineGuide.ts`(`PAKU_NOTE`) |

## 4.4 出題の説明(ガイド・冒頭の窓)

- **初回の操作ガイド**: 出題の4つの形(仕分け・穴埋め・選択式・文中タップ)ごとに、初めて遊ぶときだけ、問題の上に説明のカードを出す(「わかった!」で閉じて既読)。ことだまの書にも、初回の使い方がある。設定の「そうさの せつめい」で、もう一度出せる(`tutorialStore`、`engineGuide.ts`)。
- **ステージ冒頭の窓**: ステージを始めるたびに、出題の前に出す(途中からの再開では出さない。ボス戦の「もういちど」での再挑戦では、また出る)。通常ステージで出題の形が1つなら、その形の呼び名と場面(例: 「棚卸しを手伝う」)。形が混ざるなら、ステージのテーマ名と「いろいろな 形の 問題に ちょうせん!」。ボス戦は、専用の文言(5章)。ボタンは、通常「はじめる」、ボス戦「たたかう!」(`stageIntro.ts`)。
- **エリアごとの呼び名**(`src/data/engineFlavor.ts`):

| エリア・型 | 呼び名 | 場面の一言 |
|---|---|---|
| ことばの分かれ道・選択式 | ことだま使いの心得 | 見習いとして最初の心得を試される |
| ことばの市場 | 棚卸しを手伝う | 品物(言葉)を正しい棚に並べ直し、商売を助ける |
| 姿変えの鍛冶場 | 型を打つ | 金属を打って正しい形に鍛え直す |
| なめらかの滝・仕分け | 水路を切り分ける | 川の流れを2つの水路に正しく振り分け、詰まりを解消する |
| なめらかの滝・穴埋め | 流れをなめらかにする | 引っかかった水の流れをなめらかに整える |
| つなぎの橋・穴埋め | 橋板をかける | 抜け落ちた橋板を正しい場所にはめ込む |
| つなぎの橋・選択式 | 番人の問い | 橋の番人に正しいつなぎ言葉を答えて通してもらう |
| 絆の間 | 絆の糸をたどる | 見えなくなった関係の糸を指でなぞって結び直す |
| 見分けの間 | まやかしを見破る | 大臣の言葉のすり替えを、レンズ越しに見破る |
| 王座の間 | 作法の間 | 出された場面に合わせて、正しい敬語の言い方を選ぶ |

(表にない組み合わせは、そのエリアの基本の呼び名になる。ラスボスは、問題の所属エリアで引く。)

## 4.5 問題の選び方

出題は、完全なランダムではなく、次を組み合わせる(`src/features/selection/selectQuestions.ts`。純粋関数で、乱数を差し替えられる)。

| 規則 | 内容 | 値 |
|---|---|---|
| 層化抽出 | プールより少ない数を選ぶとき、単元ごとに1問ずつ巡回して取る(単元の順は乱数。足りない単元は他へ回る) | — |
| 直近の除外 | 直近の出題は、他に候補があるかぎり選ばない。足りなければ、古い順に再利用 | `RECENT_LIMIT = 20`(全単元まとめて直近20問。`statsStore`) |
| 連続の回避 | 同じ単元の問題が、続けて3問以上にならないよう並べる(行き止まりを避けて並べる) | `MAX_SAME_UNIT_RUN = 2` |
| 復習(星)の別枠 | 星のついた問題を、通常の枠とは別に混ぜる | `REVIEW_RATIO = 0.2` |

**場面ごとの出題**(`src/features/quiz/buildSession.ts`):

| 場面 | 出題 |
|---|---|
| 通常ステージ | そのステージのプール(8〜10問程度)の**全問**を、順番を並べ替えて出す。そこに、**復習枠**として、星のついた問題を足す: 同じ単元の、**別のステージ**の星の問題から、`max(1, round(ステージの問題数 × 0.2))` 問まで。したがって、ステージの問題数は、表示(「10問」など)より増えることがある。小ボス・ラスボスには復習枠はない |
| 小ボス | プール(そのエリアの通常ステージの全問題)から、**20問**を、層化抽出・直近除外で選ぶ(プールが20未満なら全問)。再挑戦のたびに選び直す |
| ラスボス | プール(全エリアの392画面)から、**24問**を、同じ方法で選ぶ |
| 自由練習 | 選んだ単元のプールから、**最大10問**(`FREE_PRACTICE_SIZE`)を、層化抽出・直近除外で選ぶ。ストーリー・HP・ライフなし |
| 苦手問題の練習 | 星のついた問題の全体から、**ランダムに最大10問**(`REVIEW_PRACTICE_SIZE`)。単元の層化・直近除外は使わない。星がなければ「にがて もんだいは ないよ!」 |

直近の除外(`recentQuestionIds`)が効くのは、プールより少なく選ぶとき(小ボス・ラスボス・自由練習)。通常ステージは、プールの全問を使うので、効かない。

## 4.6 苦手問題(星)と復習

| 項目 | 内容 | 根拠 |
|---|---|---|
| 星がつく | 間違えた問題に、自動で星がつく。出題中の「にがてもんだいに いれる」ボタンで、自分で付けたり外したりもできる | `reviewStore.ts` |
| 星が外れる(克服) | 星のついた問題に正解すると、星が外れる。このとき、克服の効果音が鳴り、コトが「もぐもぐ」の表情になる。**アクセサリーは増えない**(アクセサリーはエリアクリアのときだけ。7章) | `review.ts`、`mascotStore.ts` |
| 仕分けの扱い | 1回目の入れ方で、1枚でも外せば、不正解(星がつく)。やり直しで合っても、星はつく | `SortingEngine.tsx` |
| 星の数の表示 | ホーム・エリア選択の帯「苦手問題 N問・タップして練習」(押すと、苦手問題の練習へ)。ことだまの書「せいとう」の下部と、単元名の横(星の数) | `HungryBadge.tsx`、`AccuracyTab.tsx` |
| コトの表情 | 星が1問以上あると、ホームのコトが「おなかをすかせた」表情、5問以上(`SLEEPY_STAR_THRESHOLD`)で「眠そう」の表情になる | `src/features/mascot/mood.ts` |
| ボス戦でも更新 | ボス戦・自由練習・苦手問題の練習でも、星と正答率は、通常どおり更新される | `QuizPlayer.tsx` |

## 4.7 正答率と「にがて」

- **単元ごとの正答率**は、累計ではなく、**単元ごとの直近10問**(`UNIT_ACCURACY_WINDOW = 10`)の正誤で出す。古い解答は押し出される(`statsStore.unitRecent`)。
- ことだまの書「せいとう」に、単元ごとの横棒グラフ(正答率と「正解数/解答数」を文字でも出す)。行をタップすると、その単元の自由練習へ(エリアが未開放の単元の行は、押せない)。
- **「にがて」の条件**: 直近の解答が3問以上(`WEAK_MIN_ATTEMPTS = 3`)あり、正答率が60%未満(`WEAK_RATE = 0.6`)の単元。行に「にがて」の印が付く。
- 画面の最上部に「にがてかも?」の欄が出て、「にがて」の単元(開放済みのエリアのものだけ)を、正答率の低い順に並べる。タップでその単元の自由練習へ。
- **累計正解数**: 全問題のうち、**一度でも正解した問題のユニーク数**を数える(`masteryStore`)。同じ問題に何度正解しても二重には数えない。ホームに「正解した問題 N / 392問」と、進捗バーで出る。全問正解で「コンプリート!」。難易度・解放条件には影響しない。通信できるときに、サーバーへ件数だけを送る(9章)。
