# 11. 表示とアクセシビリティ

画面の大きさ・レイアウト・配色・文字(フォントとふりがな)・文字サイズ・動きの扱い・色だけに頼らない表示・操作のしかたを定める。画面の一覧は2章、音は12章、素材は13章。

## 11.1 画面とレイアウト

| 項目 | 内容 | 根拠 |
|---|---|---|
| 基準の画面 | 幅375×高さ667px(iPhone SEクラス)。e2eテストもこの大きさ | `playwright.config.ts` |
| ビューポート | `width=device-width, initial-scale=1, viewport-fit=cover`(ノッチの端まで描く)。上端と下端の余白は `env(safe-area-inset-*)` で確保 | `index.html`、`global.css` |
| 画面の向き | PWAのmanifestは縦向き固定(`portrait-primary`)。ブラウザで開いたときの横向きの崩れは**未確認** | `vite.config.ts` |
| 幅 | 各画面(`.screen`)は、**幅の上限480px**で中央に置く。パソコンの広い画面でも、スマホと同じ縦長のまま。大きい画面向けの別のレイアウトはない | `global.css` |
| 高さ | 画面の最小の高さは `100dvh`。内容が長い画面は縦にスクロールする。仕分けの出題画面は、場所を詰めた表示(`is-compact`)になる | `global.css` |
| 小さい画面 | 幅360px以下: 左右の余白を0.7remに詰める。幅380px以下: ことだまの書のタブの文字を0.75remに。高さ700px以下・660px以下: ホームの行間、言の葉の森の入口の絵・ボタンの大きさを詰める。高さ741px以上・800px以上: ホームの主要ボタンを少し高くする | `global.css` の `@media` |
| 色 | 明るい配色だけ(`color-scheme: light`)。ダークモードはない | `global.css` |
| 背景 | エリアごとの背景画像(素材があれば)。素材がなければ単色や仮の帯(13章) | 2・13章 |

- エリアごとのアクセントカラー(エリア選択・ステージ選択・出題画面の帯や線)は `src/data/areaTheme.ts`(3章)。
- 品詞の色(10種)は7章。**出題中は出さず、正解が確定したあとと、ことだまの書だけ**に出す。必ず品詞名の文字を添える。
- ブラウザのテーマ色(`theme_color`)は `#A8E0C8`、manifest の背景色は `#FBF4E4`(1章)。

### コントラストの確認(自動テスト)

`src/styles/accessibility.test.ts` が、次を確かめる(WCAGの相対輝度の式)。

| 組 | 基準 |
|---|---|

## 11.3 文字

### フォント

- 日本語フォントは **M PLUS Rounded 1c**(SIL Open Font License 1.1)。太さは400と700の2つ。アプリで使っている文字だけに絞った自前のサブセット(各約0.25MB。元は各約0.9MB)を、`src/assets/fonts/` に置き、`font-display: swap` で読み込む(`src/styles/fonts.css`)。
- 英数字は `@fontsource/m-plus-rounded-1c`。フォールバック: ヒラギノ丸ゴ、游ゴシック、システムのフォント。
- サブセットに含まれない文字(ニックネームに入れた珍しい漢字など)は、端末の標準の日本語フォントで表示される。
- `src/data` で使う文字がサブセットに含まれていることは、テストで確かめる(`fontCoverage.test.ts`)。データに新しい漢字を足したら `scripts/subset-fonts.py` を実行し直す。

### 文字の大きさ(設定で変更)

| 設定 | `<html data-text-size>` | 文字の基準 |
|---|---|---|
| 小 | `small` | 87.5%(14px) |
| 標準 | `standard` | 100%(16px)。既定 |
| 大 | `large` | 118.75%(19px) |

- 文字や余白の多くは `rem` 基準なので、1か所の変更で全画面に効く。
- 文字サイズ「大」の特別な調整: ことだまの書のタブが4つ以上のとき、2列に並べる(横にスクロールせず、見切れない)。高さ約660px以下の言の葉の森の入口では、ユライとコトの一言を出さず、絵を大きくする。

### ふりがな

ふりがなは、HTMLの `<ruby>` を使うが、配置はブラウザ標準に任せず、**CSS grid で漢字の真上に重ねて置く**(ブラウザごとに間隔が大きく違うため。iPhone の Safari では標準のままだと約3倍に開く)。DOMの順は漢字→ふりがなのまま(コピー・読み上げの順は標準と同じ)。自動テスト(`e2e/ruby-spacing.spec.ts`)がある。

データの書き方は `"漢字[ふりがな]"`。ふりがなは、直前の漢字の連続にだけ付ける(`src/data/ruby.ts`)。

| 文の種類 | ふりがなの出し方 |
|---|---|
| 出題の問題文・選択肢・解説・ストーリーの台詞・言の葉の森(ことわざ・故事成語) | データに書いたふりがなを、そのまま全部出す |
| 文法用語(品詞名・単元名・文節の関係など) | 辞書(`src/data/furigana.ts`。**100語**)にある語に、自動でふりがなを付ける。長い語を先に照合。すでに `[` が続く語、前後に別の漢字が続く語(促音便の「音便」など)は付けない |
| システム文の地の文(説明、お知らせ、画面の案内) | `<Rb>` が、**文法用語(上の100語)と、読みが難しい語**(`HARD_WORDS`。**56語**)だけ残し、ほかの漢字のふりがなは取り除く(漢字はそのまま残す) |
| 操作ボタン・短い案内(はじめる、もどる、やめる、など) | ふりがなを付けない。ひらがなのまま |
| なかまの ずかん | 文法用語と、難読語の一覧(`NAKAMA_READINGS`。20語)に記法を付け、さらに `<Rb>` の方針で絞る |
| ホームの一言 | 同じ(`homeLineText`) |

- 方針の根拠: 「操作の名前にはふりがなを付けない」(ことだまの書のタブの注記)、「常用の漢字はそのまま書き、中学生がまだ習っていない・読みが難しい漢字だけにふりがなを付ける」(`rubyPolicy.ts`)。
- ふりがなを付けたい語が出てきたら `HARD_WORDS` に足す。仲間の図鑑の難読語は `NAKAMA_READINGS` にも足す。

## 11.4 動き

- OSの「動きを減らす」(`prefers-reduced-motion: reduce`)のとき、次のアニメーションを止める: ボタンの縮み、コンボの表示、正解の演出(3種)、キラキラ、ボスのかわす動き・HPゲージの光、ストーリーの立ち絵の動き、言の葉の森・ずかんの動き(テストで確認: 言の葉の森、なかまの ずかん)。
- 画面の切り替えは、URLを使わず状態で行う(2章)。ブラウザの戻る操作とは干渉しない。

## 11.5 色だけに頼らない表示

| 場面 | 色以外の手がかり |
|---|---|
| 選択式の解答後 | 正解に「◎」、選んでしまった不正解に「×」(4章) |
| 仕分けの解答後 | 語ごとに「◎/×」。品詞の色には、品詞名の文字を添える |
| 品詞の色 | 必ず品詞名の文字を添える(`PosChip`、図鑑の例文) |
| ボスのライフ・HP | ハートの数、「HP 現在 / 最大」の文字 |
| 称号・バッジ | 称号の名前の文字を添える |
| クリア/ロック | 鍵のアイコン、「たすけてもらった」などの文字 |
| 効果音 | すべての効果音には、対応する視覚的な表示を用意する(`SPEC.md.md` 7章。音が出ない場合も意味が伝わる) |

## 11.6 操作のしかた(支援技術・キーボード)

- 画面の言語は日本語(`<html lang="ja">`)。
- 役割と名前: 進み具合・HPゲージは `role="progressbar"`(値つき)、コンボは `aria-live`、ライフは `role="img"` と「ライフ 現在 / 最大」のラベル、確認ダイアログは `role="alertdialog"`、ことだまの書のタブは `role="tablist"`/`tab`/`tabpanel`、範囲やスイッチは `radiogroup`/`switch`。ミュートボタンは `aria-pressed` と状態に応じたラベル。画像の多くは飾りとして `alt=""`(`aria-hidden`)。コード全体で、`role`/`aria-` の指定は100か所以上ある。
- キーボード: タブは左右の矢印・Home・Endで切り替え、なかまの詳細は Esc で閉じる。確認ダイアログの「いいえ」を初期のフォーカスにする(初期化の確認)。ドラッグの代わりに、仕分けはタップで選んで入れる操作がある(4章)。選択肢・カードはボタン。
- セリフの音声読み上げは実装しない(`SPEC.md.md` 7章)。
- 読み上げ・キーボードでの実際の操作性の網羅的な確認は、**未確認**(自動テストは、ふりがな・コントラスト・サブセット・一部のラベルと動きの確認に限る。15章)。
