# 10. 設定・引き継ぎ・データ

設定画面の項目、データの引き継ぎ(ひきつぎコード)、端末に保存するデータの一覧(保存キー)、データの初期化、保存の失敗への対処、お知らせを定める。サーバーに置くデータは9章、音の設定の使われ方は12章、プライバシーは14章。

## 10.2 端末に保存するデータ(保存キー一覧)

保存先は、ブラウザの localStorage。保存のしくみは、Zustand の `persist` と、失敗しても止まらない入れ物 `safeJSONStorage`(10.6)。キーはすべて `paku-kokubunpo:` で始まる。**サーバーにアカウントは作らない**。

| キー | 中身 | 引き継ぎ | 初期化 | サーバーへ送る |
|---|---|---|---|---|
| `paku-kokubunpo:progress` | `clearedStageIds`(クリアしたステージ)、`totalScore`(累計得点)、`bossLosses`(ボスに負けた回数。ステージid→回数)、`assistedStageIds`(助けてもらったステージ) | クリアしたステージと得点だけ | 消える | 得点をランキング(参加時のみ) |
| `paku-kokubunpo:mascot` | `growthStage`(0〜8) | ○ | 消える | — |
| `paku-kokubunpo:story` | `seenStoryIds`(視聴済みの場面)、`choices`(分岐の選択) | ○ | 消える | — |
| `paku-kokubunpo:review` | `starredQuestionIds`(星=苦手問題) | ○ | 消える | — |
| `paku-kokubunpo:stats` | `recentQuestionIds`(直近の問題。最大20)、`unitRecent`(単元ごとの直近10問の正誤)。版1 | ○ | 消える | — |
| `paku-kokubunpo:tutorial` | `seenGuides`(操作ガイドの既読。`sorting`・`assembly`・`choice`・`tapInSentence`・`paku`・`zukan`) | ○ | 消える | — |
| `paku-kokubunpo:profile` | `iconId`(主人公のアイコン) | ○ | 消える | アイコンをランキング(参加時のみ) |
| `paku-kokubunpo:mastery` | `correctQuestionIds`(一度でも正解した問題)、`lastSyncedCount` | ×(含まれない) | 消える | 件数だけ(`players`) |
| `paku-kokubunpo:ranking` | `classCode`、`nickname`、`lastSyncedScore`、`lastSyncedAt`、`syncedIcon` | ×(新しい端末でもう一度参加) | 消える | — |
| `paku-kokubunpo:kotonoha` | 集めた葉、まちがえた問題、入場済み、初回の台詞の既読、コンプリートの既読、直前の入口の台詞。版1 | ×(含まれない) | 消える | — |
| `paku-kokubunpo:session` | 最後に遊んでいた1ステージの途中経過(出題の並び、位置、正解数、コンボ、ボスのHPとライフ) | ×(復元時に消す) | 消える | — |
| `paku-kokubunpo:settings` | 音量、ミュート、文字の大きさ | × | 消える(既定に戻る) | — |
| `paku-kokubunpo:announcements` | 見たお知らせのid | × | 消える | — |

- 13個。ほかに、壊れた保存の退避先 `<キー>:corrupt`(10.6)と、デバッグ用のキー(存在のみ。名前と手順は書かない)がある。**全解放の保存は、キーが `paku-kokubunpo:` で始まらないため、初期化では消えない**(コードのコメント)。音のログ用のキーは `paku-kokubunpo:` で始まるので、初期化で消える。
- ほかにブラウザが持つもの: Firebase の匿名認証の状態(SDK の既定の保存)、PWA のキャッシュ(1章)。
- 保存の版: `stats`(版1。旧版は単元ごとの累計だったので、移行時に破棄)、`kotonoha`(版1。初回の台詞の既読を追加)。それ以外は版の管理がなく、読み込み時の補正(`merge`)で、足りない項目を既定値にする。
- 保存内容が壊れていたとき(JSONとして読めない): その内容を `<キー>:corrupt` へ退避し、最初の状態で始める。

## 10.3 データの引き継ぎ(ひきつぎコード)

機種変更・アプリの入れ直しのとき、進み具合を新しい端末へ移す。**サーバーを通らない**(アカウントを作らず、データもサーバーに残らない)。

### 操作

- 古い端末: せってい →「つくる」。コード(文字列)が出る。「コードを コピーする」で、クリップボードへ(使えないときは、文字を選択状態にして、手でコピーしてもらう)。同じコードの **QRコード**も出る。画面に「中身の概要」(クリアしたステージ数、得点、にがて問題の数)を出す。「このコードは、あなたのデータそのものだよ。ほかの人には見せないでね」と注意し、ランキングの参加は引き継がれないと案内する。
- 新しい端末: せってい →「いれる」。コードを貼り付ける、またはカメラでQRコードを読み取る、または QRコードの写真から読み取る。読み取ると、まず**中身(クリアしたステージ、とくてん、コトの成長 N / 7、にがて問題)を見せる**。「ふっきゅうする」を押したときだけ、この端末のデータを上書きする。「やめる」で取り消せる。復元後は「ホームへ」。
- カメラが使えないときは、「コードを貼り付けてね」と案内する。QRの読み取り(jsQR)は、読み取るときに初めて読み込む。

### コードの形式

| 項目 | 内容 | 根拠 |
|---|---|---|
| 形 | `PAKU` + 版 + 圧縮の種類(`Z`=圧縮、`R`=そのまま) + `.` + 本体(base64url) + `.` + 確認用の4文字 | `transferCode.ts` |
| 版2(いまの発行) | ステージ・問題・場面などの id を、3バイトの「指紋」(FNV-1aの下位24ビット)で持つ。全部遊び終えても約1000文字。QRコードに収まる。一覧にない指紋(データの更新で消えた id)は飛ばす。idの追加・並び替えがあっても、別の版のアプリで復元できる | `transferV2.ts` |
| 版1(以前の発行) | id をそのまま JSON にして圧縮。**読み取りだけ**対応 | `transferCode.ts` |
| 確認用の文字 | FNV-1a を英数字4文字にしたもの。写し間違い・途中で切れたコードを検出 | 同上 |
| 貼り付け | 空白・改行・全角の空白は、取り除いて読む | 同上 |
| エラー | 空、形がちがう、読めない版、壊れている。やさしい日本語で出す | 同上 |

### 含まれるもの・含まれないもの

| 含まれる | 含まれない |
|---|---|
| クリアしたステージ、累計得点、コトの成長段階、ストーリーの既読と選択(=称号)、苦手問題の星、直近の問題と単元ごとの直近の正誤、操作ガイドの既読、アイコン | 音量などの設定、途中経過(復元時に消す)、ランキングの参加状態(新しい端末で、もう一度クラスに入る。得点は移した値から続く)、**累計正解数の記録(`mastery`)**、**ボスに負けた回数**、**「助けてもらった」の印**、**言の葉の森の記録**、お知らせの既読 |

- コードに書かれた値は、復元時に検証する(形、範囲、存在するid)。存在しないステージ・問題のidは取り除く。個数の上限は5000、文字は120文字まで、得点は10,000,000まで、アイコンは一覧にあるもの、成長段階は0〜8の整数(`MAX_GROWTH_STAGE`。王座の間のクリアで8)。
- 引き継ぎでサーバー側(`players`・`classes`)が移ることはない。

## 10.5 データの初期化

設定の一番下の「データを初期化する」。確認の文(「進み具合・得点・ストーリー・図鑑・アイコン・ランキング参加など…すべて消して、最初の状態に戻すよ。音量の設定も最初に戻るよ。ランキングに参加中なら、順位表からも抜けるよ(通信できないときは、順位表にデータが残るよ)。本当に初期化しますか?」)を出し、「はい」で実行する。「いいえ」が初期選択。

1. ランキングに参加中なら、先にクラスから抜ける(自分の順位表のデータを削除)。通信できなくても、端末のデータは消す。
2. `paku-kokubunpo:` で始まるキーを、すべて消す(音量・ミュートも含む。**残すキーはない**)。
3. 音を止め、画面を読み込み直す。

- **サーバーの `players/{uid}`(累計正解数)は消さない**(消す処理がコードにない)。9章のルールは、累計正解数を**減らせない**ので、初期化のあと遊び直すと、送る件数が以前のサーバーの値以下の間は、更新がルールに拒否される。コードは、拒否を「失敗」として握りつぶし、次の機会にまた送る(画面にエラーは出ない)。実機での確認は**未確認**(ルールとコードからの推論)。
- Firebase の匿名認証の状態は、初期化では消えない(10.2)。

## 10.6 保存の失敗

- 書き込みに失敗したとき(容量がいっぱい、プライベートブラウズなど)は、例外を投げず、「保存できていない」と知らせる。メモリ上の進み具合は、アプリを開いているあいだは続くので、遊びは止まらない。
- 画面の上部に、お知らせ「この端末に、進み具合を保存できていないよ。アプリを閉じると消えてしまうかも。『ひきつぎコード』でひかえておいてね。」と、「ひきつぎコードを つくる」「とじる」を出す(`StorageWarning`)。閉じると、次に失敗するまで出さない。保存できるようになると、消える。
- 保存の領域そのものが使えないときは、読み込みで「何もない」として扱う。

## 10.7 お知らせ

最初の画面(「タッチして はじめる」)のバージョン表記から開く。見ていないお知らせがあるあいだ、バージョン表記の近くに「NEW」を出す。開くと、すべて見たことにする。

- データ: `src/data/announcements.ts`(15件。新しいものを先頭に足す)。日付、見出し(「〜しました」)、箇条書き。やさしい「です・ます」調。ユーザーに見える変更があれば、デプロイのたびに足す(`docs/VERSIONING.md`)。
- idは、見たかどうかの記録に使う(変えると、また「NEW」が出る)。
