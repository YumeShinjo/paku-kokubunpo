# 9. 称号・成績・ランキング

称号、成績(得点・正答率・累計正解数)、クラス内ランキング、サーバー(Firestore)に置くデータとそのルール、匿名認証を定める。正答率と「にがて」は4章、エンディングの流れは6章、保存キーは10章、プライバシーは14章。

## 9.1 称号

称号(二つ名)は2種類ある。**どちらも、称号そのものは保存せず、記録から導く**。

| 称号id | 名前 | もらえる条件 | 導き方 | 根拠 |
|---|---|---|---|---|
| `castle` | 言葉を結びし者 | エンディングの分岐で「城に戻り、王家の一員として過ごす」を選ぶ | `storyStore.choices["ohzaNoMa-ending-choice"]` が `castle` | `src/data/titles.ts` |
| `journey` | 風のことだま使い | 同じ分岐で「これからも、ことだま使いの相棒として旅を続ける」を選ぶ | 同上が `journey` | 同上 |
| `kotonoha` | 言の葉をひろいし者 | 言の葉の森の葉を、**80枚ぜんぶ**集める | `kotonohaStore.collectedIds` が全80問を含む(`hasAllLeaves`) | `titles.ts`、`kotonohaStore.ts` |

- 称号の選択キー(`castle`・`journey`)は、`events.ts` の `ending-choice` の選択肢と一致させる(テストで検証)。
- エンディングの称号は、**分岐を選び直すと変わる**(6章の見返し)。選択は保存し直される。同じ端末に称号は1つ(選択は1つだけ保存)。
- 授与の場面: エンディングでは、結果画面(`endingResult`)「エンディング おつかれさま!」で「しょうごう(二つ名)を てにいれた!」とバッジを出し、「(条件)ので、この二つ名がついたよ。」と添える(称号の授与の効果音)。一度見たあとは、ラスボスを再び倒しても繰り返さない(3章)。言の葉の森の称号は、80枚目の結果画面で、コンプリートの会話のあとにユライから授与する(8章)。
- 表示: ホーム(タイトル)画面に、エンディングの称号と進捗(平らな表示)。ことだまの書の「おもいで」タブに、エンディングの称号(もらうまでは「？？？(エンディングで てにはいるよ)」)。言の葉の称号は、ことだまの書の「ことのは」タブ(80枚そろっているとき)に出る。**ホームと「おもいで」タブには、言の葉の称号は出ない**。
- バッジの見た目: 称号バッジ画像(`ui/badge-<称号id>`)が置かれていれば添え、なければ王冠のアイコン(`TitleBadge`)。画像が置かれているかは、リポジトリに素材がないため**未確認**(13章)。
- 称号の一覧(全解放の隠しデバッグ機能がオンのときだけ見える)が、「おもいで」タブにある(存在のみ)。
- 言の葉の称号の名前は、データのコメントで「仮の名前」(8章)。

## 9.2 成績

| 指標 | 内容 | 保存・送信 | 詳細 |
|---|---|---|---|
| 得点(累計) | ステージをクリアするたびに、**10点×正解数**を足す。再クリアでもまた足す。「先へすすむ」(助けてもらったクリア)では足さない。ボス戦の負けでも足さない。自由練習・苦手問題の練習・言の葉の森では足さない | 端末(`progressStore.totalScore`)。ランキングに参加していれば、サーバーへ送る | 3章 |
| クリアしたステージ | ステージidの一覧 | 端末 | 3章 |
| 単元ごとの正答率 | 単元ごとの**直近10問**。「にがて」=3問以上で60%未満 | 端末(引き継ぎに含む) | 4章 |
| 累計正解数 | 全問題のうち、**一度でも正解した問題のユニーク数**(分母は392) | 端末(`masteryStore`)。サーバーにも件数だけ送る(9.4) | 4章 |
| 星(苦手問題) | 間違えた問題の一覧 | 端末(引き継ぎに含む) | 4章 |
| 最大コンボ・正解数 | ステージの結果画面にだけ出す | 保存しない | 3・4章 |
| 言の葉の森の葉 | 集めた葉の数(N / 80) | 端末のみ(引き継ぎに含まない) | 8章 |

- 得点は、**ランキング以外では表示しない**(ホーム画面には、累計得点を出していない。ランキング画面の「あなたの とくてん」だけ)。
- 成績の画面: ホームの進捗バー(累計正解数)、ことだまの書の「せいとうりつ」(4章)、ランキング画面(得点・順位)。

## 9.3 ランキング

### 仕様

| 項目 | 内容 | 根拠 |
|---|---|---|
| 範囲 | 同じ**クラスコード**を入れた人どうしだけの順位。クラスの一覧は取れない(合言葉を知っている人だけが見られる) | `rankingApi.ts`、`firestore.rules` |
| 指標 | 累計得点だけ。週間などの期間区切りはない | `SPEC.md.md` 8章、コード |
| 参加 | クラスコードとニックネームを入れる。メールアドレス・パスワードなし。匿名認証(9.5)。アイコンも選べる(8種)。ランキング画面で選び、順位表に出る | `RankingScreen.tsx` |
| クラスコード | 先生が決める合言葉。2〜20文字。**文字・数字・「-」「_」だけ**。先頭が `__` は不可。全角半角をそろえ(NFKC)、前後の空白を除き、英字は小文字にする(「ABC」と「abc」は同じクラス) | `inputRules.ts` |
| ニックネーム | 1〜12文字。全角半角をそろえ、前後の空白を除き、連続する空白は1つにする。制御文字は不可。NGワードを含むものは不可 | `inputRules.ts` |
| NGワード | 簡易チェック。**含んでいたらNG**の語41個と、**全体が一致したらNG**の語24個(「名前の一部に自然に入る短い語」を誤って弾かないため)。分類: 暴力・自傷をあおる、性的、罵倒・差別、汚い言葉、英語。正規化(NFKC・小文字・カタカナ→ひらがな・記号や空白や長音を除く)したうえで判定。表記の揺れ・当て字はすり抜けることがあり、クラス内にしか見えない設計で補う、とコメントにある(語の一覧は、ここには載せない) | `ngWords.ts` |
| 共有用URL | `?class=合言葉` を付けて開くと、クラスコードの入力欄に入る(発表会などでURLやQRを配るため) | `inputRules.ts`(`readClassCodeFromUrl`) |
| 参加フォームの注意書き | 「クラスコードは、ほかの人に推測されにくい合言葉にしてください」「ニックネームに、本名・学校名など、自分だとわかる名前は入れないでください」 | `RankingScreen.tsx` |
| 順位表 | **上位30人**まで(`fetchRanking` の `limit = 30`)。得点の高い順。同点は同順位(1, 2, 2, 4 …)。上位30に入っていないときは、自分の行を別に取り、自分より得点が高い人数+1を自分の順位にする。自分の行は強調し、上位3位は印が付く | `rankingApi.ts` |
| 更新 | リアルタイムでは見ない(読み取りの回数を抑える)。画面を開いたときと、「こうしん」を押したときだけ取得する | 同上 |
| 参加後にできること | ニックネームの変更、アイコンの変更、クラスを抜ける(自分のデータをサーバーから削除。確認あり) | `RankingScreen.tsx` |
| 参加中の表示 | クラスコード、アイコン、ニックネーム、「あなたの とくてん」と現在の順位。まだ送れていない得点があるとき「まだ送れていない得点があるよ。通信できると自動で送るよ。」 | 同上 |
| 抜けたあと | 端末の参加情報(クラスコード、ニックネーム、送信済みの得点)を消す。端末の累計得点は残る | `rankingStore.ts` |

### 得点の送り方(同期)

- 得点は端末の累計(`totalScore`)。サーバーへ送るのは「いまの累計」だけ。未送信があるかは、累計が送信済みの得点を超えているかで判定する(別のキューは持たない)。
- 送るタイミング: ステージのクリア時、アプリの起動時、通信が戻ったとき(`online` イベント)、ランキング画面を開いたとき。
- 一度に増やせる量には上限がある(不正対策)。端末側も同じ上限を守って送り、たまっている分が多いときは、上限までを送り、残りは次の機会に送る。上限に近くて進められる分が50点未満のときは、送信を見送る(`MIN_SEND_STEP = 50`)。
- 送信中に得点が増えたら、続けてもう一度送る(取りこぼし防止。最大3回)。
- 通信は10秒(`NETWORK_TIMEOUT_MS = 10000`)で打ち切り、「つうしんできない」として扱う。失敗しても得点は端末に残り、次の機会に再送される。
- 接続は、通常の方式が通らないネットワークでは、自動でロングポーリングに切り替える(`experimentalAutoDetectLongPolling`)。
- エラーの種類: 未設定、オフライン、ルールに拒否された、匿名認証が未有効、その他。画面にやさしい日本語で出す。

### 得点の上限(端末とルールで同じ値)

| 項目 | 値 | 意味 |
|---|---|---|
| `JOIN_MAX_SCORE` | 5000 | 新しく参加(作成)するときの得点の上限。たまっている分は、参加後に少しずつ送る |
| `BURST_SCORE` | 500 | 前回送った時刻がわからない端末が、最初の1回で進められる分 |
| `SLACK_SCORE` | 10 | 更新1回ごとの上乗せ |
| `RATE_SCORE_PER_SEC` | 8 | 1秒あたりに増やせる点(0.8問分) |
| `MAX_DELTA_SCORE` | 20000 | 1回の更新で増やせる上限 |
| `MAX_SCORE` | 200000 | 得点の総量の上限。減らせない |

更新1回で増やせるのは、`10 + 8 × 前回の更新からの経過秒数` 点、かつ20000点まで(`firestore.rules` では、`(増えた点) × 1000 ≦ 10 × 1000 + 経過ミリ秒 × 8`)。

## 9.4 サーバー(Firestore)のデータとルール

プロジェクトの設定値は環境変数 `VITE_FIREBASE_*`(1章)。未設定ならランキングは「まだ使えないよ」。Firebase SDK(認証、Firestore)は、ランキングか累計正解数を送るときに初めて読み込む。**サーバーに置くのは、次の2つだけ**。ストーリーの進み、ステージのクリア、正答率、星、言の葉の森の葉は、サーバーに送らない。

### コレクション

| パス | 内容 | 誰が読めるか | 誰が書けるか |
|---|---|---|---|
| `classes/{クラスコード}/members/{uid}` | `nickname`(文字列)、`score`(整数)、`updatedAt`(サーバー時刻)、`icon`(任意。アイコンのid) | ログイン(匿名認証)済みの人。ただし、クラスの一覧は取れない(`/classes/{クラスコード}` 自体にはルールがなく拒否される)ので、クラスコードを知っている人だけが、その `members` を読める | 自分のドキュメント(ドキュメントID=自分の uid)だけ |
| `players/{uid}` | `correctCount`(累計正解数)、`updatedAt`(サーバー時刻) | **自分だけ** | 自分だけ |

### ルールの要点(`firestore.rules`)

`classes/.../members/{uid}`:

| 操作 | 条件 |
|---|---|
| 形式 | キーは `nickname`・`score`・`updatedAt`・(任意で)`icon` だけ。`nickname` は文字列で1〜48文字(アプリ側は12文字まで)。`score` は0〜200000の整数。`icon` は文字列で1〜32文字。`updatedAt` はリクエスト時刻と一致 |
| 読み取り | ログイン済み |
| 作成 | 自分のドキュメント、クラスコードが1〜80文字、形式が正しい、得点が5000以下 |
| 更新 | 自分のドキュメント、形式が正しい、得点が**減らない**、増える量が20000以下、増える量が「10点+経過時間×8点/秒」以下 |
| 削除 | 自分のドキュメントだけ |

`players/{uid}`:

| 操作 | 条件 |
|---|---|
| 形式 | キーは `correctCount`・`updatedAt` だけ。`correctCount` は0〜2000の整数 |
| 読み取り・削除 | 自分だけ |
| 作成 | 自分だけ、形式が正しい |
| 更新 | 自分だけ、形式が正しい、`correctCount` が**減らない**。増え方の上限は設けない(競争に使わないため) |

- **ルールが防げないこと**(コメントに明記): 得点はアプリが計算して送るので、悪意のある端末が、上限の範囲で自分の得点を盛ることまでは防げない(答えあわせをサーバーで行う仕組み=有料プランの Cloud Functions がないため)。防いでいるのは、他人のデータの書き換え・削除、桁外れの値、急激な増え方、形式の崩れ。
- 累計正解数(`players`)は、**書き込みだけ**行い、サーバーの値を端末へ読み戻さない(端末でデータを初期化したときに、古いサーバーの値で上書きされる食い違いを避けるため)。送るのは、件数が前回送った件数を超えたとき(ステージのクリア時、起動時、通信が戻ったとき)。ランキングに参加していなくても貯まる。
- インデックス: `firestore.indexes.json` は空(複合インデックスなし)。
- Firebaseのプラン: `SPEC.md.md` 8章は、無料の Spark プランと書く(コードからは確認できない)。

## 9.5 匿名認証

- ランキングへの参加・得点の送信・順位の取得・累計正解数の送信のたびに、Firebase の**匿名認証**(`signInAnonymously`)で uid を得る。すでにサインイン済みなら、そのまま使う。ユーザー名・パスワード・メールアドレスは使わない。
- uid は、ランキングのドキュメントIDであり、累計正解数のドキュメントIDでもある。
- 匿名認証が未有効のとき(`auth/operation-not-allowed`)は、「ランキングの準備がまだ終わっていないよ」と出す。
- **未確認**: 匿名認証がコンソールで有効かどうか、デプロイ済みのルールがリポジトリの `firestore.rules` と同じかどうか(コードからは確認できない。`docs/SPEC_STATUS.md` は「本番反映済み・動作確認済み」と書く)。端末の uid が、データの初期化・ブラウザのデータ削除・引き継ぎでどうなるか(Firebase SDK の既定の保存に任せている。コードは uid を保存していない)。
