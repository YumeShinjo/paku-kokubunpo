# 効果音・BGMの一覧(2026-10-15)

アプリが鳴らす音の、ファイル名・使う場面・出典の状況・長さ・音量の一覧。
音声ファイルそのものは Git に置いていない(`src/assets/audio/` は `.gitignore` で除外。曲の二次配布の禁止のため)。

- **ファイルの場所は1か所**: `src/assets/audio/bgm/<場面>.mp3` と `src/assets/audio/se/<種類>.mp3`。同じ名前のファイルを置けば、コードを変えずに差し替わる。
  名前の決め方は `src/assets/registry.ts`(効果音は `seAssetName`、BGMは `findBgm`)。効果音の種類は `src/lib/audio.ts` の `SeKind`。
- **音量(LUFS)**: Chromium で MP3 をデコードして、ITU-R BS.1770 の方式(K特性フィルタ・400msのブロック・ゲート)で、全体の統合ラウドネスを測った値。
  ピークは、デコード後の最大の振幅(dBFS)。0.0 に近いほど、割れやすい。4秒に満たない効果音は、ブロックが少なく、参考値。
- **出典の状況**: 「確認済み」は、入手元ページと規約を確認できたもの。「要確認」は、規約の本文または入手元ページが未確認(くわしくは `docs/ASSET_CREDITS.md`)。

- **サンプルレート**: 全11ファイルが 44100 Hz(48000 Hz・22050 Hz のものはない)。`audioFormat.test.ts` の確認とも合う。
- **チャンネル**: 全部ステレオ。
- **VBR**: なし(全ファイルが、全フレームで同じビットレートの CBR)。1ファイルの中で、サンプルレートやビットレートが途中で変わるものもない。
- **基準(128kbps)との差**: `title`(ホーム)・`subBoss`・`lastBoss`・`ending` が 96kbps、`stage` が 192kbps。ビットレートは音質とファイルサイズの違いで、再生の速さ(ピッチ)には関わらない。
  サンプルレートの食い違い(ピッチが変わる原因になりうるもの)は、どのファイルにもない。
- **ホームのBGM(`title.mp3`)の特徴**: 96kbps の CBR。LAVC(ffmpeg)でエンコードされ、先頭に Info ヘッダーがあり、フレーム数(3290)が実際の数と一致する。ID3v2.4 のタグが 6119 バイト付いている(音声データではない)。
  ループ再生(`audio.loop = true`)の継ぎ目には、エンコーダ遅延(576サンプル)と末尾の余白(576サンプル)ぶん、約26msの無音が入りうる(ピッチには関係しない、つなぎ目の小さな間)。

### BGMの再生方式(曲ごと。2026-10-16)

曲ごとに、2つの方式のどちらで鳴らすかを決めている(`src/lib/bgmPolicy.ts`)。

- **buffer**: fetch → decodeAudioData(曲の直前に1回)→ AudioBufferSourceNode(loop)。実機のログで、アプリの切り替えからの復帰・約10分の連続再生でも、ピッチも時計も正常だった
- **audio**: `<audio>` 要素 → MediaElementSource → GainNode(これまでの方式)
- **基準**: デコード後のメモリ(長さ × 44100 × 2チャンネル × 4バイト)が **36MiB 以下なら buffer**、超えたら audio(長い曲は、メモリが大きいので、audio のまま)。上限は `BUFFER_MAX_BYTES`(bgmPolicy.ts)。長さが分からない曲は audio
- 導入曲つきの2曲は、2曲とも buffer のときだけ buffer。音量補正(audioLevels)・フェード・ミュート・裏に回ったときの停止と復帰は、どちらの方式でも同じ経路(同じ GainNode)
- 設定の「音のログ」(`?audiodebug=1` かバージョン表記を5回タップ)の「B無効」をオンにすると、すべて audio 方式(不具合のときの逃げ道)
- 長さは `src/assets/audioLevels.ts` の `AUDIO_DURATION_SEC`。曲を差し替えたら、書き換える(テストが、置かれているMP3の実際の長さと照らす)

## 音量の補正(素材ごとのゲイン。2026-10-15)

`src/assets/audioLevels.ts` に、測定値と、そこから決めた補正(dB)の表がある。補正は、Web Audio のゲインの値を変えるだけ(`lib/audio.ts`)。再生の仕組み(停止・再開の経路)は変えていない。
- BGM: 統合ラウドネスを -16 LUFS にそろえる(補正 = -16 - 測定値)。曲を切り替えるとき(場面の曲・導入曲からループ曲へ)に、その曲の補正をかける。
- 効果音: ピークが -1 dBFS 以下になるようにする。音は大きくしない(下げるだけ)。
- 素材を差し替えたら、`AUDIO_MEASURED` の測定値を書き換える(補正は自動で決まる)。専用のファイルがない `subBossPurify` は、`subBossClear` のファイルと補正を使う。

## 場面ごとの、音が鳴っているか

| 場面 | 鳴る音 |
| --- | --- |
| 通常ステージの敵を倒す(クリア) | `clear` |
| 小ボス(メイほか)を倒す | 命中ごとに `correct`。HPが0になって、結果画面に切り替わった瞬間に `subBossPurify`(いまは `subBossClear` のファイルを使う)。「先へすすむ」の場面でも、ボスが浄化される3行目で鳴る |
| ボス戦の正解 / 不正解 | `correct` / `incorrect`(通常ステージと同じ音。メッセージだけ「ヒット!」「はずれた!」) |
| ボス戦の撃破 | 小ボスは `subBossPurify`、ラスボスは `lastBossClear` |
| ドラッグ問題でカードを置く | マウス・ペン・指のどれでも、置いたときに `tap` が1回鳴る(2026-10-15 に、そろえた。ドラッグの終わりの click は、アプリ全体のタップ音に届かないようにしている) |
| ドラッグ問題でカードを戻す(別のカゴへ入れ直す) | 置くときと同じ(専用の音はない) |
| タップ選択(カードを押す→カゴのボタンを押す) | それぞれ `tap` |
| 言の葉の森で80/80そろったとき | 専用の音はない。そのラウンドの最後の `roundEnd` と、結果画面のユライ・コトの台詞(`complete_all`)だけ |

## 差し替えやすさ(小ボスを倒したときの音)

- 小ボスを倒したときに鳴るのは、専用の種類 `subBossPurify`(`src/assets/audio/se/subBossPurify.mp3`)。ファイルがなければ、`subBossClear.mp3`(素材名「衝撃」)を使う。
- 新しい音は、`src/assets/audio/se/subBossPurify.mp3` として置けば、コードを変えずに差し替わる(`AUDIO_MEASURED` に `se/subBossPurify` の測定値を足し、台帳(`docs/ASSET_CREDITS.md`)にも1行足すこと)。
- `subBossClear` は、7エリアの小ボスすべてと、称号の授与の画面(`EndingResultScreen`)で共通。メイだけ別の音にしたいときは、効果音の種類を1つ足す(`SeKind` と `StageScreen` の1か所)。
